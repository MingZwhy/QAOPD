# Exact dependency set for the EVALUATION env (python 3.10), replayed with --no-deps:
#
#   conda create -y -p venvs/qaopd-eval python=3.10
#   venvs/qaopd-eval/bin/pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cu128
#   PIP_INDEX_URL=https://pypi.org/simple venvs/qaopd-eval/bin/pip install --no-deps -r env/requirements-eval.txt
#   venvs/qaopd-eval/bin/pip install -e 3rdparty/edgerazor --no-deps
#
# Why this file exists (env/requirements-edgerazor.txt cannot be installed):
# that file is a raw `pip freeze` and pins `torch==2.9.1+cu128` /
# `torchvision==0.24.1+cu128`. The `+cu128` local-version segment only exists on
# download.pytorch.org, never on PyPI, so the `pip install -r` in
# docs/INSTALL.md section 2 dies with "No matching distribution found for
# torchvision==0.24.1+cu128" and NOTHING gets installed -- including lm_eval and
# deepspeed. Same failure mode as the old env/requirements-verl.txt.
#
# --no-deps is required, not an optimisation, for the same reason as
# requirements-train.txt: this is a closure snapshot, not a solvable spec.
#
# `pip install -e 3rdparty/edgerazor` must ALSO carry --no-deps. Without it pip
# resolves edgerazor's unpinned `torch` requirement and silently upgrades the
# env to the newest PyPI torch (observed: 2.9.1+cu128 -> 2.13.0+cu130), which
# swaps the whole CUDA stack underneath you and does not report an error.
#
# Excluded from the original freeze, deliberately:
#   * torch / torchvision / nvidia-* / triton / cuda-* -- installed from the
#     cu128 index above, not PyPI. The freeze contained BOTH cu12 and cu13
#     nvidia wheels (an artifact of the accidental upgrade on the source host);
#     replaying them would re-break the CUDA stack.
#   * edgerazor -- installed editable from 3rdparty/
